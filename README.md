# 团队工作台（Team Tracker）

一个跑在本机的小团队跟踪站点：看板、计划和时间线、KPI、事务提醒、成员周报与团队周报。
零第三方依赖 —— 只要系统自带的 `python3`（3.6+），数据存放在同目录的 `data.db`（SQLite）。

## 启动

```bash
./start.sh          # 启动并打开浏览器（默认 http://127.0.0.1:8770）
```

手动启动：

```bash
python3 server.py            # 首次运行会写入一份示例数据
PORT=9000 python3 server.py  # 换端口
python3 server.py --empty    # 空库启动（不写示例数据）
```

停止：`pkill -f "python3 server.py"`（或前台运行时 Ctrl+C）

## 功能

| 页面 | 内容 |
| --- | --- |
| 总览 | 进行中 / 本周完成 / 逾期 / 待跟进四个指标；每人在忙什么、KPI 达成；最近进展；待处理提醒 |
| 看板 | 待办 → 进行中 → 待验收 → 阻塞 → 已完成 五列，**卡片拖拽即改状态**，点击打开详情抽屉 |
| 计划 | 全部事务表格：负责人、状态、优先级、进度、起止日期、预估工时，可按人/状态/逾期筛选 |
| 时间线 | 按成员分组的甘特视图，今天一条竖线，条内浅色部分是已完成进度 |
| KPI | 每人若干指标（目标 / 当前 / 单位 / 周月季 / 越高越好或越低越好 / 权重），± 按钮快速调当前值 |
| 提醒 | 逾期、阻塞、临期（≤2 天）、停滞（≥4 天无进展）、未排期；可一键标记完成或延期 3 天 |
| 周报 | 每人提交自己的周报 → 全员提交后生成团队周报，也可先生成草稿；可复制或下载 `.md` |
| 团队 | 成员增改、头像、IP 绑定、每人事务分布，以及「清空数据」用于从示例数据切换成真实团队 |

### 身份识别（按 IP + 验证码）

- 顶栏右侧是身份胶囊。第一次在一台机器上打开站点，会弹出人员网格：点自己的名字 → 输入 4 位验证码 → 记住这台设备；下次打开直接就是你。
- 验证码取成员手机号的**中间 4 位**（11 位手机号的第 4–7 位），界面上只写「验证码」，输入框是遮罩显示。手机号只存在本机数据库，接口不会把它发给浏览器，前端只能看到 `138****5678` 这样的掩码。
- 连续输错 5 次锁 10 分钟（按 IP）。
- 没有登记手机号的成员，只能在本机（localhost）确认身份；远程会自动提示「这位成员还没登记手机号，请联系王少君」。
- 网格最后一项是「参观一下」：不是团队成员的人可以只读浏览（看板、计划、时间线、KPI、周报都能看），不能改动数据——后端对游客的写请求一律 403。游客可以留一个称呼，方便在访问记录里认出来。
- 想换人：点顶栏身份胶囊重新选；想解除绑定：团队页「编辑」里把 IP 清空。

### 成员管理仅限本机

「添加成员 / 编辑成员 / 移除成员 / 清空数据」只接受来自 localhost 的请求。用 `http://<本机IP>:8770` 从别的机器打开时，团队页只显示成员列表，不显示这些按钮（后端同样会拒绝，不只是前端隐藏）。

### 左侧「站点访问」统计

侧栏左下角按 IP 汇总：有身份对应关系的显示人名，没有的显示 IP（游客显示他留的称呼），后面是访问次数；点「查看全部访问记录」看明细：IP、系统登录用户、设备名、浏览器/系统、次数、最近时间。

- 登录用户：只有从本机（localhost）访问时能读到系统账号；
- 设备名：远端机器靠 NetBIOS（`nmblookup`）/ 反向解析 / DNS 反查，局域网里的 Windows 机器一般能拿到计算机名，拿不到就留空——浏览器本身没有权限读取对方的账号名。

### 头像

团队页每行的「头像」按钮，或编辑成员里的「上传图片」。浏览器端会裁剪成 256×256 再上传，落盘在 `avatars/`，不塞进数据库。

### 变更日志

详情抽屉底部是「变更日志」：创建、状态、负责人、优先级、进度、日期、预估等每个字段的改动都记一条，带操作人和时间。操作人取自 IP 身份，认不出时记「系统」（例如脚本直接调接口）。

### 周报流程

- 周期固定为**上周五 ~ 本周四**（周三打开时显示 2026/10/30 ~ 2026/11/05），左右箭头翻周期，不能翻到未来。
- 左栏是「我的周报」，可以点「带入我的统计」把自己这周的完成/进行中/风险列进去，再补充文字后「提交周报」。一人一周一份，重复提交会覆盖。
- 右栏是「提交情况」，实时显示 `已提交 N / 7`。
- 全员提交后「生成团队周报」解锁；没齐时可以点「先生成草稿」（会标注谁还没交）。

其余细节：

- 详情抽屉里可以改负责人、状态、优先级、进度，写「进展记录」；状态变更会自动记一条历史，周报的“最新进展”取的就是这里（不含系统记录）。
- 快捷键：`n` 新建事务，`Esc` 关闭抽屉/弹窗。
- 看板拖拽、KPI ±、提醒里的快捷动作都是直接写库，刷新不丢。

## 数据

- 数据文件：`data.db`（与 `server.py` 同目录）。备份就是复制这个文件：
  `cp data.db data-$(date +%F).db`
- 头像在 `avatars/`，备份时一起拷走。
- 换成你自己的团队：进入「团队」页 → 清空数据 → 添加成员 → 建事务 / KPI。
- 也可以直接用 sqlite3 改：`sqlite3 data.db "select id,title,status from tasks"`

## HTTP 接口（需要脚本对接时用）

```
GET    /api/bootstrap              成员 / 事务 / KPI / 进展 / 变更日志全量
GET    /api/whoami                 按请求 IP 识别当前成员
POST   /api/whoami                 {"member_id": N} 绑定当前 IP 到某人
GET    /api/reports?week=YYYY-MM-DD  某周期的提交情况（week 为周五）
POST   /api/reports                {"week_start": "...", "content": "..."} 提交/覆盖我的周报
GET    /api/reports/draft?week=     我的周报草稿（按我的事务自动汇总）
GET    /api/report?start=&end=     团队周报 Markdown（format=md 直接返回文本）
POST   /api/members/<id>/avatar    {"data": "data:image/jpeg;base64,..."} 上传头像
POST   /api/tasks                  新建事务
PATCH  /api/tasks/<id>             局部更新（status=done 会自动补 done_at 和 100% 进度）
DELETE /api/tasks/<id>
POST   /api/tasks/<id>/updates     追加进展记录
POST   /api/members  PATCH/DELETE /api/members/<id>
POST   /api/kpis     PATCH/DELETE /api/kpis/<id>
POST   /api/reset                  {"seed": true} 重置为示例数据 / {"seed": false} 空库
```

## 说明

- 监听 `0.0.0.0:8770`，局域网内同事用 `http://<本机IP>:8770` 就能访问，各自按自己的 IP 被识别。
- 没有登录口令，身份靠 IP + 验证码，属于小团队内部工具，不要直接暴露到公网。
- 示例数据里的成员、事务、KPI 都是占位内容，清空后换成真实数据即可。
- 代码仓库：<https://github.com/shao-jun/team-tracker>（MIT）。`data.db`、`avatars/` 属于运行时数据，已在 `.gitignore` 里排除，不会上传。
